## 테스트를 쓸 때 지킬 것

### 1. 확률은 결정적 RNG로

`Math.random()`에 기대지 마라. 모든 확률 함수는 `Rng`를 인자로 받는다.

```ts
import { seededRng } from '../rng'
const result = resolveStep(ctx, choice, seededRng(42))  // 항상 같은 결과
```

분포를 확인해야 하면 시드를 바꿔가며 충분히 반복한다. 한두 번의 무작위 결과로 판단하지 않는다.

```ts
for (let s = 0; s < 200; s++) expect(sum(gen(s).stats)).toBe(C.total)
```

### 2. 판정 함수는 순수 함수다

`src/game/*.ts`는 React 없이 import해서 바로 테스트할 수 있어야 한다.
테스트하기 어렵다면 그건 로직이 UI로 새어 나갔다는 신호다.

### 3. 상태를 바꾸는 함수는 복제본에 대고 부른다

`emit()`, `travelTo()`, `buyItem()` 등은 인자로 받은 상태를 **직접 수정**한다.
스토어가 `structuredClone` 후 부르는 것을 전제한다. 테스트에서도 같은 규칙을 지킨다.

### 4. 공정성 규칙은 테스트가 지킨다

아래는 사람이 눈으로 확인할 게 아니라 테스트가 막아야 한다.

- 시작 능력치 총합이 모든 캐릭터에서 같은가
- 성별·나이를 바꿔도 능력치·체형·키가 같은가
- 행운 보정이 `luckRange × luckMult`를 넘지 않는가
- 지점 간 능력치·보상 차이가 없는가

이 테스트를 고쳐야 할 상황이 오면, 먼저 그게 정말 의도한 설계 변경인지 확인한다.

### 5. 새 시스템에는 최소 이만큼

| 항목 | 확인할 것 |
|---|---|
| 해금 | 조건 미달 시 **이유가 나오는가** · 준비 중 콘텐츠는 조건을 채워도 안 열리는가 |
| 보상 | 실제로 지급되는가 · **중복 수령이 막히는가** |
| 저장 | 직렬화 → 복원 후 값이 같은가 |
| 마이그레이션 | 신규 필드가 없어도 살아나는가 · **여러 번 돌려도 결과가 같은가(멱등)** |
| 데이터 참조 | 콘텐츠 검사(`validateContent()`)에 오류가 0인가 |
| 효과 | 장비·칭호·스킬이 **판정 수치를 실제로 바꾸는가** (before/after 비교) |

## 콘텐츠 검사

`src/content/validate.ts`가 끊어진 id 참조·중복 id·해금 불가 콘텐츠를 잡는다.

- 테스트: `systems.test.ts`의 "끊어진 참조나 중복 ID가 없다"
- 화면: 개발 빌드 → 메뉴 → 개발자 도구 → 콘텐츠 검사

`errors`는 게임이 깨지는 것, `warnings`는 의도한 골격일 수도 있는 것이다.
(예: "커리어 car-pro: 아직 활동이 없다 (준비 중)"는 정상이다.)

## 모바일 검수 (수동)

Playwright는 아직 없다. 개발 서버를 띄우고 390×844에서 확인한다.

```bash
npm run dev   # http://localhost:8950
```

F12 → `Ctrl+Shift+M` → iPhone 15 Pro (390×844)

### 검수 기준

| 항목 | 기준 |
|---|---|
| 가로 스크롤 | 없어야 함 |
| 하단 탭바 | 맨 아래로 스크롤했을 때 가려지는 요소 0개 |
| 최소 글자 | 11px 이상 |
| 주요 버튼 | 40px 이상 (캐릭터 터치 영역은 44px) |
| 모달 | 연속으로 뜨지 않을 것 · 화면 밖으로 잘리지 않을 것 |
| 콘솔 | 오류 0 |
| 새로고침 | 상태가 유지될 것 |
| 잠긴 기능 | 조건이나 "서버 연결 필요"가 보일 것 |

### 검수할 흐름

```
신규 캐릭터 생성 → 홈짐 선택 → 일정 편성 → 등반 → 프로젝트 진척
→ 퀘스트 보상 → 장비 구매 → 장비 장착 → 다른 지점 방문
→ 부산 원정 → 미니대회 → 기록·도감 확인
```

개발자 도구(메뉴 → 개발자 도구)로 레벨·돈·해금을 올려두면 뒷부분을 빨리 확인할 수 있다.

## 개발자 도구

**개발 빌드에서만** 보인다. 운영 빌드에서는 메뉴 항목 자체가 사라지고,
스토어의 `devApply()`도 아무 일도 하지 않는다.

| 기능 | 용도 |
|---|---|
| +1일 / +1주 | 일정 진행·오프라인 리포트 확인 |
| 레벨 · 돈 · 능력치 | 후반 콘텐츠 빨리 열기 |
| 몸 상태 회복 / 피로·부상 세팅 | 경고·부상 차단 확인 |
| 암장 전부 방문 · 지역 해금 · 명성 | 원정·해금 흐름 확인 |
| 전 장비 지급 | 장비 효과 확인 |
| 세이브 내보내기 | 버그 재현용 상태 복사 |
| 콘텐츠 검사 | 데이터 오류 확인 |
