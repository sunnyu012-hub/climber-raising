# 밸런스 문서

모든 숫자의 단일 출처는 **`src/game/balance.ts`** 다. 이 문서는 그 값의 의미와 조정 방향을 설명한다.
숫자를 바꿀 때는 `balance.ts`를 고치고 이 문서를 같이 갱신한다.

## 1. 시간
| 상수 | 값 | 의미 |
|---|---|---|
| `time.dayMs` (prod) | 30분 | 게임 내 하루 = 실제 30분. 한 주 = 3.5시간 |
| `time.dayMs` (dev) | 30초 | 개발 중 빠른 검증용 (`import.meta.env.DEV`) |
| `time.timeScale` | 1 (설정에서 1/6/30/60) | 개발자 배속. 운영 기본은 항상 1 |
| `time.offlineCapHours` | 12시간 | 오프라인 인정 상한. 초과분은 버린다 |
| `time.offlineCapDays` | 30일 | 한 번에 소화하는 최대 일수. 배속을 올려도 수천 일이 한 번에 돌지 않게 막는다 |
| `time.tickMs` | 1000 | UI 틱 주기 |

## 1-1. 캐릭터 생성 (공정성)
| 상수 | 값 | 의미 |
|---|---|---|
| `creation.total` | **76** | 8능력치 시작 총합. **모든 캐릭터가 동일**하다 |
| `creation.min` / `max` | 6 / 13 | 능력치 하나의 허용 범위 |
| `creation.specialtyBonus` | 2 | 주특기가 옮겨오는 점수. 다른 능력치에서 그대로 빼오므로 총합은 그대로 |
| `creation.masteryMin` / `Max` | 4 / 10 | 주특기 무브의 시작 숙련도 |
| `creation.startingMoney` | 30,000원 | 나이·성별과 무관하게 동일 |
| `creation.ageMin` / `Max` / `Default` | 18 / 60 / 28 | 나이 입력 범위 |

**공정성 규칙 (테스트로 강제)**
- 성별을 바꿔도 능력치·체형·키가 **완전히 같다** — `generateCharacter()`에서 성별/나이는 rng를 소비하지 않는다.
- 나이를 바꿔도 능력치와 시작 소지금이 같다. 특정 나이가 유리하지 않다.
- 어떤 시드로 뽑아도 총합은 항상 76이고, 각 능력치는 6~13을 벗어나지 않는다.
- 체형(짧은/균형/긴 리치)은 능력치를 바꾸지 않는다. 등반 판정에만 연결된다.
- 키는 표시용이다. reach와 중복으로 성공률에 적용하지 않는다.
- 웨이브락 3지점은 능력치·보상이 동일하다(`homeBonus: []`).

**배분 방식** — 전 능력치를 `min`(6)에서 시작해 남은 28점을 한 점씩 무작위로 뿌린다(`max`에 걸리면 다른 곳으로).
그 뒤 주특기 능력치로 2점을 다른 능력치에서 옮겨온다.

**성격 패시브** — 8종 모두 아주 작은 효과 하나씩. 압도적인 성격이 없도록 크기를 맞춘다.
| 성격 | 효과 |
|---|---|
| 일단 해보는 편 | 다이노 +3%p |
| 안전한 베타 선호 | 관절 소모 ×0.96 |
| 실패할수록 불타오름 | 멘탈 +1 |
| 사람들과 함께할 때 강함 | 인맥 +1 |
| 혼자 프로젝트를 파는 편 | 중간 홀드 경유 +3%p |
| 장비를 꼼꼼히 챙김 | 초크 사용 +3%p |
| 몸 상태를 잘 살핌 | 회복 ×1.05 |
| 이상한 베타를 좋아함 | 루트파인딩 +1 |

## 2. 능력치 → 성공률
```
chance = base
       + statWeight  × clamp((가중능력치 - statPivot) / statScale, -1, 1)
       + masteryWeight × (숙련도/100)
       - fatiguePenalty × (피로/100)
       - hpPenalty × max(0, (50 - 체력)/50)
       - jointPenalty × 관절부담
       - gradeScale × 난이도지수
       + 리치보정 + 스킬보정 + NPC보정
       + 행운보정
```
| 상수 | 값 | 의미 |
|---|---|---|
| `climb.statWeight` | 0.30 | 능력치가 성공률에 주는 최대 폭 ±30%p |
| `climb.statPivot` | 10 | 기준 능력치. 시작 캐릭터는 대부분 8~11 |
| `climb.statScale` | 12 | 기준에서 12 벌어지면 최대치 |
| `climb.masteryWeight` | 0.18 | 숙련도 100이면 +18%p |
| `climb.fatiguePenalty` | 0.25 | 피로 100이면 -25%p |
| `climb.hpPenalty` | 0.15 | 체력 0이면 -15%p (체력 50 이상은 패널티 없음) |
| `climb.jointPenalty` | 0.20 | 해당 무브가 쓰는 관절이 망가질수록 최대 -20%p |
| `climb.gradeScale` | 0.045 | 난이도 1단계당 -4.5%p |
| `climb.minChance` / `maxChance` | 0.05 / 0.95 | 확정 성공/실패 금지 |

## 3. 행운 (상한 있음)
| 상수 | 값 |
|---|---|
| `climb.luckRange` | 0.10 → 일반 문제에서 ±10%p |
| `climb.luckStatScale` | 60 → 행운 능력치가 기댓값을 위로 밀어줌(폭은 그대로) |
| `BetaChoice.luckMult` | 1.0 기본 / 무모한 베타 1.8~2.2 |
| `climb.luckyEventChance` | 0.06 → 추락이 "귀여운 구조 사건"으로 바뀔 확률 |

**규칙: `|행운보정| ≤ luckRange × luckMult`.** 테스트로 강제한다(`climb.test.ts`).
행운은 결과를 흔들 뿐 성장을 무력화하지 못한다.

## 4. 결과 4단계
성공률 `p`를 뽑은 뒤 난수 `r`:
```
r < p × critRatio(0.22)          → 대성공
r < p                            → 성공
r < p + (1-p) × partialBand(0.45) → 부분 실패(버티기)
그 외                              → 추락
```

## 5. 소모
동작마다 `hp / fatigue / joint` 기본 소모가 있고,
`costByOutcome`(대성공 0.8 / 성공 1.0 / 부분실패 1.25 / 추락 1.4)을 곱한다.
숙련도가 높으면 `masteryCostRelief`(0.30)만큼 소모가 준다 → 숙련 100이면 -30%.

## 7. 직접 플레이 보너스
| 상수 | 값 | 의미 |
|---|---|---|
| `directPlay.bonusRatio` | 1.45 | 자동 진행 대비 145% (요구 범위 130~160%) |
| `directPlay.diminishStep` | 0.15 | 같은 날 반복할수록 `1/(1+0.15n)` |
| `directPlay.diminishFloor` | 0.45 | 아무리 반복해도 45% 아래로 안 내려감 |
| `directPlay.speedupPerStepRatio` | 0.06 | 동작 1회 성공 = 하루의 6% 단축 |
| `directPlay.speedupOnClearRatio` | 0.18 | 완등 = 추가 18% 단축 |
| `directPlay.onsightBonus` | 1.5 | 초견(첫 도전 완등) 경험치 배수 |

한 문제(5동작) 완등 = 하루의 최대 48% 단축. 하루에 여러 문제를 풀어도
`diminishFloor` 때문에 무한 가속은 안 된다. **접속 못 한 사람도 일정은 계속 돈다.**

## 8. 피로 · 관절 · 부상
관절 값은 "건강도"(100 = 멀쩡).
| 단계 | 범위 | 표시 |
|---|---|---|
| 건강 | ≥ 85 | 🙂 |
| 주의 | ≥ 70 | 😐 |
| 뻐근함 | ≥ 50 | 😖 경고 시작 |
| 통증 | ≥ 30 | 😣 강한 경고 + 등반 만류 |
| 부상 | < 30 | 🤕 등반 불가, 재활만 |

| 상수 | 값 |
|---|---|
| `injury.warnAt` | 55 (뻐근함 경고) |
| `injury.blockClimbAt` | 30 (등반 차단) |
| `injury.overtrainFatigue` | 75 (과훈련 경고) |
| `injury.passiveFatigueRecovery` | 하루 4 |
| `injury.passiveJointRecovery` | 하루 3 |
| `injury.riskPerHardStep` | 0.015 기본, 피로/관절 상태로 최대 6배 |
| `injury.strainFatigue` | 30 — 이 아래 피로면 부상 판정을 아예 굴리지 않는다 |
| `injury.strainJoint` | 88 — 이 위로 관절이 멀쩡하면 부상 판정을 아예 굴리지 않는다 |

**부상 전에는 항상 경고가 먼저 뜬다.** (`character.ts: buildWarnings()`)
그리고 **피로도 관절도 멀쩡하면 부상 판정 자체를 굴리지 않는다** — 첫날부터 다치는 일은 없다.
부상은 무작위 처벌이 아니라 누적된 선택의 결과여야 하기 때문이다.

## 9. 현재 임시 값 / 추후 조정
- `time.dayMs` 30분은 감이지 검증값이 아니다. 실제 플레이 테스트 후 조정.
- 문제 난이도(V0~V4)의 `gradeScale` 선형 가정 — V5 이상 추가 시 비선형으로 바꿔야 할 수 있음.
- 알바 수입(3,000~12,000원)은 장비 가격이 없어 아직 의미가 약하다. 장비 구현 시 같이 조정.
- `luckStatScale`은 행운 능력치를 올리는 빌드가 재미있는지 확인 후 재조정.
- NPC 친밀도 보너스는 현재 소폭(+2%p). 원정/할인 구현 시 재배분.
- 시작 능력치 총합 76(평균 9.5)은 `statPivot` 10에 맞춘 값이다. 문제 난이도를 올리면 같이 조정한다.
- 성격 패시브 8종의 체감 차이는 아직 검증 전이다. 특정 성격이 강하게 느껴지면 크기를 다시 맞춘다.
- 세 지점의 유불리를 없앤 것은 실제 시설 특성을 확인하지 못했기 때문이다.
  사용자 피드백으로 지점 성향이 정해지면 `Gym.homeBonus`에 넣고 이 문서에 기록한다.

## 조정 대기
- 원정 비용(교통비 ×2)은 감이지 검증값이 아니다. 원정 빈도를 보고 조정한다.
- 명성 획득량(원정 20 · 대회 3~50 · 업적 5~30)과 상위 지역 요구치(200~5000)의 비율은 미검증.
- 커리어 해금 일수(중급 30일)는 실제 플레이 속도를 보고 조정한다.
- 장비 효과 크기(3~8%p)가 스킬(4~10%p)과 겹친다. 둘 다 붙었을 때 과한지 확인 필요.
